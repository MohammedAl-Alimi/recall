Terminal session manager for Claude Code

Every Claude Code session, one keypress away.

Claude Code deletes your transcripts after 30 days and hides the rest behind the directory you started them in. recall keeps them, lists them all, and reopens the one you pick in the way that loses the least. In the terminal, or in a local web dashboard.

Three things it fixes

recall reads the files Claude Code already writes. No account, no network, no daemon.

01 · retention

Nothing deleted behind your back

Claude removes transcripts after cleanupPeriodDays, 30 by default. recall setup raises it to a number you choose and installs a hook that archives each session under ~/.recall when it ends, so a session from last spring still resumes. recall archive --all covers the sessions you already have.

02 · focus, attach, resume

The reopen that loses the least

Still running in a Terminal.app tab? recall focuses that tab. Kept alive in tmux? recall attaches. Closed? recall runs claude --resume in the right directory with the flags you started it with. Pick where it opens with --terminal terminal, iterm or cmux.

03 · needs you

Waiting sessions come to you

A session blocked on a permission prompt sorts to the top as Needs you, can raise a macOS notification, and after it exits the pending tool call is still shown so you know where it stopped.

Dashboard

recall serve opens the same list in your browser. Every session is a card. Click Open and a Terminal.app tab runs the resume command, or the tab it already lives in comes to the front. With cmux installed, Open in cmux gives the session its own workspace. Local only, token-protected, never on the network.

Everything the list does Search, filter chips, pin, label, hide, fork, copy the resume command. Cards refresh every few seconds while a session works.
Where it opens Open uses a new Terminal.app tab, or focuses the tab a live session is already in. Open in cmux appears when the cmux app is installed and creates a workspace running the resume command.

What stays, honestly

recall cannot bring back what was never written to disk. This is the whole truth about what survives a closed tab, a reboot, or Claude's retention.

ThingWho deletes itWith recall
TranscriptClaude, after cleanupPeriodDays (default 30)Kept: retention raised, hard-linked into the archive, resumable from there
Context windowWith the transcriptKept: rebuilt by --resume; compactions counted
Typed promptsNever pruned by Claude todayKept: mirrored; deleted sessions still show as ghosts with their prompts
Launch flagsGone at exitKept: recorded by the SessionStart hook, replayed on resume when the paths exist
Running processGone with the tab or a rebootKept sessions run in tmux and survive the tab, not a reboot
ScrollbackGone with the tabKept sessions hold 50000 lines; plain sessions rely on the transcript
Background shell jobsLost on exitCounted and shown as a warning before you resume
Pending permission promptLost on exitShown as Needs you while live; the dangling tool call is shown afterwards
Tool results, file snapshotsWith the transcriptCopied only with archive --sidecars; not needed to resume
Labels, pins, notesOnly youYours, in ~/.recall/meta.json

recall never resumes with bypassPermissions, never sends anything over the network, never reads key files or tokens, and never writes into ~/.claude except the two setup steps you confirm, each with a .bak copy.
